## 7. Decisões Arquiteturais Importantes (ver DECISIONS_LOG para detalhe)

### Páginas individuais de praia: SPA

- **Decisão original (Mar 2026):** `beach.html?id=UUID` com render dinâmico via JS + Supabase
- **Razão:** velocidade desenvolvimento (80+ praias)
- **Trade-off oculto descoberto 15/05:** Google rastreia mas não vê conteúdo → "Rastreada, não indexada"
- **Status:** decisão pendente — pre-render top 30 praias (caminho A ou C)

### URLs sem `.html` (15/05/2026)

- **Decisão:** sitemap.xml e canonicals apontam para URLs sem extensão
- **Razão:** Cloudflare faz 301 automático `.html` → sem extensão; sitemap antigo criava 135 "Página com redireccionamento"
- **Implementação parcial:** sitemap fixo (`41c478b`); canonicals em 101 ficheiros adiados pela mesa

### Redesign monetização v2 com entidades HTML (14/05/2026)

- **Bug histórico:** commit `1e269a2` partiu produção HTTP 500 por double-encoding UTF-8
- **Reverted:** `47594c3`
- **Re-implementação:** entidades HTML (`&eacute;`, `&middot;`, `&mdash;`, `&#8470;`) em `65d73cc`
- **Lição permanente:** SEMPRE entidades HTML para acentos PT em automatização
### Sistema editorial de parceiros (21/05/2026)

- **Decisão:** vitrine pública `/escolas-de-surf` separada de `/parceiros.html` (landing B2B)
- **Razão:** URL semântica para SEO, preserva landing indexada, escalável para `/operadores-pesca/`, `/hoteis-verificados/` etc.
- **Implementação:** `_data/partners.json` → `_scripts/build-partners.mjs` → HTML estático bilingue
- **Detalhe:** ver AD-20260521-01
### Checklist mobile pre-deploy obrigatório (26/05/2026)

- **Decisão:** smoke test mobile real é obrigatório antes de qualquer deploy que toque HTML/CSS partilhado (nav, footer, header, body classes, JS de navegação)
- **Razão:** smoke test só `curl HTTP 200` não detectava bugs visuais em mobile; 3 bugs nav + drawer + toolbar chegaram a produção por este gap
- **Critérios:** desktop 1280px PT+EN + mobile 412×915 Android UA PT+EN + lang switcher + menu hambúrguer + G10 browser-level. Não passa = sem deploy
- **Gap operacional:** `Playwright.click()` programático bypassa hit-test visual → usar `Page.tap()` com `hasTouch:true` + `isMobile:true` para testar overlays reais
- **Detalhe:** ver AD-20260526-01

### Smoke test visual obrigatório de assets — extensão a AD-20260526-01 (26/05/2026)

- **Decisão:** antes de upload Supabase de logo/foto de parceiro, comparação visual lado-a-lado com asset existente do mesmo tipo (Good Feeling/Future Eco)
- **Razão:** sanity checks numéricas (yellow_count, black_count, transparent_corners) podem estar verdes com asset visualmente errado — logo Albufeira foi para produção a ~15% canvas vs ~85% dos outros e passou todos os checks numéricos
- **Critérios:** ±15% de ocupação linear do canvas vs referência. Sem comparação visual lado-a-lado = sem upload
- **Aplicação:** pedir logo SVG/vectorial directamente ao parceiro no email inicial de outreach (evita round-trip de processamento raster)
- **Detalhe:** ver AD-20260526-01b

### Hash auto-open accordion em vitrines parceiros (26/05/2026)

- **Decisão:** `js/partners-directory.js` ganha `openCardByHash()` registado em DOMContentLoaded + hashchange events
- **Razão:** URLs partilháveis tipo `/escolas-de-surf#good-feeling-surf-school` (usados em outreach) chegavam ao card mas accordion não auto-expandia — UX confusa
- **Race condition corrigida:** `applyFilters() → writeURLState() → history.replaceState` strippava hash. Fix: capturar `_startHash` antes de `init()`
- **Detalhe:** ver AD-20260526-05

### Redesign vitrines com directory list (25/05/2026)

- **Decisão:** vitrines `/escolas-de-surf` + `/en/surf-schools` usam lista compacta + sidebar filtros + accordion expand (mockup B)

- **Razão:** LemonSqueezy KYC rejeitada (27/04), Paddle recurso negado (25/05). Modelo de negócio em categoria de risco para parceiros bancários
